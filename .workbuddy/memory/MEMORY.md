# 项目长期记忆：zhibodou AI 直播管控系统

- **真实工程目录**：`E:\zhibodou-ai\zhibodou`（WorkBuddy 默认 workspace 是 C 盘，但代码实际在 E 盘，别找错地方）。
- **子目录约定**：`src/` 主程序与启动脚本；`scrcpy/` 投屏与 adb 二进制；`apk/` 手机端输入法/剪贴板 apk；`ut/` 端到端测试。
- **路径原则**：`core/paths.py` 用「向上查找同时含 `scrcpy/` 与 `src/` 的目录」作为项目根（`BASE_DIR`），`THIS_DIR=SRC_DIR`(src)。**禁止**用 `os.getcwd()` 或裸命令名（`adb` 需写全 `scrcpy/adb.exe`）。⚠️ 历史坑：`paths.py` 曾被移进 `src/core/` 后 `BASE_DIR` 算错一级导致 adb/scrcpy/apk 全找不到（FileNotFoundError）——已改为向上搜索根目录修复。改目录结构后这是第一检查点。
- **依赖**：见 `requirements.txt`；tkinter 为标准库。`ut` 测试脚本现在**直接 import 新模块**（`input_text` / `ui_locator` / `adb_utils` / `doubao`），不再 exec 单体文件。
- **运行方式**：双击 `src/一键启动.bat`（启动 `python main.py`）。
- **📦 已重构为包结构（2026-08-24）**：原 `src/zhibodou_full.py`(1100行) 拆为 18 个单职责模块，并归并到 7 个功能包，**入口 = `src/main.py`**。包布局：`core/`(paths,state,doubao) · `settings/`(config,auth) · `device/`(adb_utils,ui_locator,input_text) · `screen/`(win_embed,scrcpy_embed,capture,danmu) · `broadcast/`(live,power) · `audio/`(tts) · `gui/`(ui,dialogs)。导入一律用绝对导入（以 `src/` 为根），如 `from gui.ui import set_status`、`from settings.config import load_config`、`from device.adb_utils import adb_shell`；`main.py` 开头把自身目录插入 `sys.path`。模块设计见 `MODULES.md`。关键约定：全局状态集中到 `core/state.py`（用 `state.xxx`）；UI 控件以 `gui.ui.xxx` 模块级变量暴露；按钮回调在 `main.py` 统一接线（`gui.ui.build_ui()` 不绑定业务回调，避免 `gui.ui` 反向依赖）；`adb devices` 必须用 `device.adb_utils.run_adb(['devices'])` 而非 `adb_shell('devices')`。旧单体保留为 `zhibodou_full.py.bak` 仅供对照。
- **⚠️ .bat 文件编码铁律**：`.bat` 必须用 **GBK(cp936) + CRLF(`\r\n`)** 保存。仅 UTF-8→中文乱码截断命令词；仅 LF→`cmd` 把 `if`/行界解析错乱（表现为 `'0'`/`'errorlevel'` 被当命令、误进 python `>>>` 交互模式）。维护用 Python `open(..., encoding="gbk", newline="")` 且内容内联 `\r\n`；**严禁**用 Write/Edit 工具（写 UTF-8 且默认 LF，会破坏）。heredoc 传反斜杠会被吞，用 `chr(92)` 或占位符构造路径分隔符。
- **⚠️ ADBKeyboard 必须"启用"才能用**：`pm install` 装上 ≠ 系统已启用。未启用时 `ime list -s` 看不到它，`ime set <id>` 报 `Unknown input method ... cannot be selected`（三星/Android 常见）。代码已改为：动态解析真实 IME ID（`get_adbkeyboard_ime_id`）+ 发送前自动 `ime enable` + 切换后重新 `tap_input_box()` 聚焦再发广播。若三星仍拦截 `ime enable`，需用户手动去设置→语言与输入法→启用 ADBKeyboard。
- **🆕 豆包就绪检测（2026-08-24）**：新增 `device/doubao_check.py`，提供 `check_doubao_ready()` 只读体检——⓪豆包**是否已安装**(`device.adb_utils.is_app_installed` 用 `pm list packages` 精确匹配包名，未装直接报 ❌) ①adb设备在线 ②豆包已运行且在**前台**(查 `mResumedActivity`/`mTopResumedActivity`/`mFocusedApp`，比旧版只查 `dumpsys window` 含包名更准，后台误判已修) ③处于**对话界面**(控件树有 `DOUBAO_INPUT_ID`) ④界面**无遮挡**(`mCurrentFocus`/`TYPE_SYSTEM_ALERT`/`TYPE_APPLICATION_OVERLAY` 不是豆包) ⑤**可发送**(输入框存在且 enabled)。该检测已接入 `power.power_on_self_check()` 与 `power.startup_readiness_check()`（后者在 `main.py` 建 UI 后后台线程跑，结果写 `gui.ui.log_screen` + 状态栏）。**离线降级**：无 adb 设备时 `check_doubao_ready()` 返回 `mode='offline'`、不阻塞程序，给出「手动模式」指引（人工确认豆包状态+手动操作）；重连 adb 后自动恢复在线体检。全部只读，不点击/不输入。
- **🆕 灭屏/锁屏自动唤醒拉起豆包（2026-08-24）**：新增 `device/wake_unlock.py`，解决手机灭屏时程序无法操作豆包的问题。能力：`is_screen_off()`(`dumpsys power` 查 `mWakefulness=Asleep/Dozing`)、`is_keyguard_locked()`(`dumpsys window policy` 查 `STATE_UNLOCKED`/`isStatusBarKeyguard`)、`wake_screen()`(`input keyevent 26`)、`launch_doubao()`(`monkey -p com.larus.nova` 拉起，回退 `am start`)、`enter_first_conversation()`(轻量尝试点进第一个对话，已在对话页则直接 True)、`ensure_doubao_awake_and_foreground()`(一键恢复，返回 `(ok,msg,need_manual_unlock)`)。**边界**：无锁屏/滑动锁屏 → 全自动亮屏+拉起豆包到对话页；PIN/密码/图案锁屏 → 只能亮屏停在解锁界面，需用户手动解锁（`need_manual_unlock=True`）。已接入两处：① `check_doubao_ready()` 在线分支最前做灭屏优先检测；② `input_text.send_text_to_doubao()` 发送前先恢复灭屏（避免黑屏假阴性误报）。
