## 2. 总体目标

本轮修改集中解决以下问题：

1. VAD 未听到豆包声音、弱音误判、播放未结束就切换话术、固定播放时长错误中断等问题。
2. 保持正式音频链路为 `scrcpy → CABLE Input → CABLE Output → VAD`，禁止静默切换到其他音频方案。
3. 更换手机后 ADB 固定/比例坐标点错输入框和发送按钮的问题。
4. 豆包返回解释、对话或提示语，而不是直接输出主播口播的问题。
5. 将弹幕采集从独立 HTTP/Flask 服务集成进桌面客户端，并增加 UI 开关与 headless 支持。
6. 修复打包后 Playwright/asyncio、弹幕协议解析和 Android Agent 的兼容性问题。

## 3. VAD 与音频状态机

### 3.1 设备与校准

文件：`src/audio/vad.py`

- 保留 CABLE/VoiceMeeter/立体声混音等数字回环设备识别。
- 数字回环继续使用配置阈值和迟滞，避免破坏已经调通的 CABLE 链路。
- 增加实体麦克风自适应分支，用于诊断或显式选择麦克风时按静音底噪计算阈值。
- 实体麦克风开口阈值使用底噪加动态余量，最低保护值为 `-65dB`。
- 实体麦克风结束阈值调整为静音 P90 上方 `0.5dB`，增强轻声段识别。
- 实体麦克风结束确认至少为 8 秒，避免句内弱音或短停顿导致抢话。
- 每次正式开播建立一次可信麦克风基线；后续基线若比首轮高 1.5dB 以上，视为豆包可能仍在播放，不发送下一句。
- 校准日志增加模式、底噪、开口阈值、结束阈值和结束确认时间。

### 3.2 加权平滑

- VAD 实时平滑由简单窗口平均改为指数加权：

```text
平滑值 = 上一次平滑值 × 5/8 + 最新采样值 × 3/8
```

- 连续轻声会逐步反映到平滑值。
- 单个环境噪声尖峰不会立即改变麦克风 VAD 状态。
- 数字回环仍保留原始帧兜底，避免 PCM 分包或空帧造成漏检。

### 3.3 状态机安全策略

- 维持 `WAITING → SPEAKING → ENDED` 三态流程。
- 进入 `SPEAKING` 前累计有效语音帧，不要求所有帧连续越阈值。
- 实体麦克风结束阶段采用 1.2 秒窗口累计语音，过滤孤立噪声。
- `VAD_START_TIMEOUT` 不再当成“豆包没有回答并继续下一句”，而是安全停播。
- 音频不可用、连续读取失败和用户取消分别处理。
- 完全移除单句 45 秒/300 秒硬上限；豆包播放多久都只由 VAD 连续静音决定结束。
- 只有 `VAD_ENDED` 能释放下一条话术。

### 3.4 直播层处理

文件：`src/broadcast/live.py`

- VAD 错误提示细分为音频采集失败、等待开口超时等真实原因。
- 发生不确定状态时停止自动直播并保持 `can_next_speak=False`。
- 启动直播时重置本次会话的可信静音基线。
- 将 VAD 实际采用的结束确认时间同步到 UI 日志。

## 4. CABLE、scrcpy 与手机系统兼容

文件：`src/screen/scrcpy_embed.py`、`src/settings/config.py`、`src/settings/config.json`

### 4.1 正式音频链路

最终配置恢复并固定为：

```text
scrcpy 输出：CABLE Input (VB-Audio Virtual Cable)
VAD 输入：CABLE Output
```

- 不再为了兼容某一台手机而自动修改全局配置为实体麦克风。
- 配置保存采用“读取现有配置后更新 UI 字段”，防止保存产品信息时删除 VAD/CABLE 高级配置。

### 4.2 播放设备校验

- scrcpy 启动前枚举 Windows 输出设备。
- 校验配置设备是否存在，并核对 Windows 默认播放设备。
- 修复“实际为 Realtek 扬声器，却打印音频进入 CABLE”的硬编码错误日志。
- CABLE、VoiceMeeter、实体麦克风分别打印真实路由说明。
- `--require-audio` 保留在 Android 11+ 音频启动模式中，防止只有画面、VAD 永久静音。

### 4.3 Android 版本预检

- 通过 ADB 读取 `ro.build.version.sdk`。
- Android 11/API 30 及以上继续使用 scrcpy 音频转发。
- Android 10/API 29 及以下不支持 scrcpy 音频转发。
- API<30 且配置为 CABLE/VoiceMeeter 时明确拒绝启动并说明原因，不伪装成功。
- 代码保留“显式实体麦克风配置时只投屏画面、声音留在手机”的兼容分支，但当前正式配置为 CABLE，因此不会自动进入该分支。
- 当前检测过的华为 EML-AL00 为 Android 10/API 29，不能通过 scrcpy 向 CABLE 输送音频；该限制属于手机系统/scrcpy 能力，不是阈值问题。

## 6. ADB 文本注入与无障碍 Agent

### 6.1 PC 客户端发送链路

文件：`src/device/input_text.py`

- 主通道仍为 Android 无障碍 Agent 的 `/inject_and_send`。
- Agent 返回 `{"code": 0}` 时正确判定成功，避免重复发送。
- 删除原生 ADB 兜底中的固定/比例坐标：
  - 旧输入框坐标：屏宽 × 0.45、屏高 × 0.94。
  - 旧发送坐标：屏宽 × 0.92、屏高 × 0.94。
- 新兜底通过 `uiautomator dump` 读取 Android UI 树。
- 输入框按 `com.larus.nova:id/input_text` 或 `EditText` 定位。
- 文本/语音切换按 `action_input` 或“文本输入”描述定位。
- 发送按钮按 `com.larus.nova:id/action_send` 或“发送”语义定位。
- 找不到控件时明确失败，不再猜测右下角位置。
- 新手机若没有安装/启用 Agent，会明确打印语义兜底提示。
- 实测新手机曾因旧比例坐标误入豆包图片选择页；新逻辑会识别当前没有聊天输入框并停止。

## 7. 弹幕采集客户端集成

详细审计见 `doc/DANMU_AUDIT.md`。

### 7.1 架构调整

原链路：

```text
Playwright → 每批消息创建线程 → HTTP POST → Flask 127.0.0.1:7979
桌面客户端 → 另一套 ws://127.0.0.1:8899
```

新链路：

```text
Playwright 页面监听
→ 平台协议解析
→ message_callback
→ 2000 条有界 Queue
→ Tk 主线程每 100ms 批量更新 UI 和状态
```

### 7.2 采集器

文件：`src/danma/main.py`、`src/danma/__init__.py`

- 将独立脚本重构为 `DanmuBrowserCollector`。
- 支持 `headless`、直播 URL、用户数据目录、Chrome 路径、消息回调和日志回调。
- 支持持久化浏览器 Context，保存登录 Cookie/localStorage。
- 支持配置 Chrome、PATH、注册表及常见安装目录发现。
- 优先使用 Playwright `channel="chrome"`；仅用户明确指定时使用 `executable_path`。
- 实现 `browser_close()` 和停止信号，避免客户端退出后浏览器残留。
- 浏览器异常后由客户端桥接层执行 2～30 秒指数退避重连。
- 修复固定工作目录和 `setting.ini` 路径依赖。
- 移除每批弹幕创建线程并发送 HTTP 的逻辑。

### 7.3 客户端桥接

文件：`src/screen/danmu.py`、`src/core/state.py`

- 新增 `start_danmu_capture()`、`stop_danmu_capture()`、`toggle_danmu_capture()`。
- 新增采集代次 `danmu_generation`，避免快速重启时旧线程覆盖新状态。
- 新增 `online_num`、`like_cnt`、`gift_cnt`、`comment_cnt`、`last_danmu_text`。

- Tk 控件只在主线程更新，避免后台 Playwright 线程直接操作 Tk。
- 弹幕采集失败只记录错误，不阻断 VAD 和话术直播。

3. 若必须使用该 Android 10 手机和 CABLE，需要额外的手机音频采集桥接，例如物理音频输入再经 VoiceMeeter 路由；当前项目未实现该硬件链路。
4. 新手机需安装并启用智播豆无障碍 Agent，否则只能使用较慢的 ADB UI 树语义兜底。
5. 弹幕协议为平台非公开协议，真实直播间仍需逐平台验收。
6. Headless 首次登录、验证码和平台风控仍需人工处理。
7. `build/rth_asyncio.py` 必须在提交时显式纳入版本控制。
8. `src/settings/config.json` 包含运行环境与直播间配置；提交前需确认是否作为模板提交，避免带入真实账号或直播间敏感信息。
