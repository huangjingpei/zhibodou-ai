# 直播话术持续轮询、在线人数区间匹配与彻底停播实现方案

## 问题背景与用户需求

用户提出的核心诉求与现存问题：
1. **话术持续轮询，绝不自行中断**：只要用户没有点击「停止直播」，话术必须持续不断地轮询下发并播报，不能在中途自动停止。
2. **在线人数区间匹配**：界面上的区间01、02、03（`r1_min`~`r1_max`, `r2_min`~`r2_max`, `r3_min`~`r3_max`）对应当前直播间在线人数判断。每轮下发前，根据当前直播间在线人数 (`state.online_num`) 动态判断落在哪个区间，播报该区间对应的话术要求生成的播报内容。
3. **播放完一条话术后自动跳到下一条继续播**：修复目前播放完一个话术后没有跳到下一个需要播的话术的问题。
4. **点击「停止直播」时真正彻底停播**：只有用户点击了停止播放，程序才算真正停止，并让豆包立即停止发出声音（手机端静音/停止播放媒体），停止虚拟声卡流与弹幕采集等功能。

---

## 核心根因分析

通过对现有代码和日志的时序分析，排查出以下关键问题：
1. **切话术中断/死锁根因**：
   - 现有代码在第二轮及后续轮次中，若静音校准 `calibrate_idle` 因豆包尾音或虚拟声卡残存电平未在 3 秒内达到绝对静音基线，代码直接执行了 `_halt_live_from_worker(...)`，将 `state.is_broadcasting` 置为 `False` 并禁用按钮，导致自动直播彻底永久停止！
   - 若豆包大模型思考或生成 500 字话术耗时较长（超过 15 秒），VAD 返回 `VAD_START_TIMEOUT`，代码同样直接调用了 `_halt_live_from_worker(...)` 杀死直播循环！
2. **区间匹配缺失**：
   - 现有的 `auto_live_loop` 采用写死的 `seq_index = (seq_index + 1) % 3` 顺次轮播，根本没有读取 `state.online_num`，也未与界面上的三个区间范围进行比对判断。
3. **停止直播未让手机豆包立刻停止发声**：
   - 目前 `stop_live()` 仅重置了 PC 端的标志位和抓屏，未向手机端发送媒体停止指令，导致用户点击停止后，手机上的豆包仍在继续读完上一条很长的话术。

## 拟修改方案

### 1. [src/broadcast/live.py](file:///e:/zhibodou-ai/zhibodou/src/broadcast/live.py)

#### (1) 新增区间匹配与话术动态获取函数 `select_script_by_online_count()`
- 实时获取界面或配置中的区间数值（`r1_min`~`r1_max`, `r2_min`~`r2_max`, `r3_min`~`r3_max`）以及对应话术（`cmd1`, `cmd2`, `cmd3`）。
- 优先从 UI 输入框实时读取（用户在界面改动无需手工点“保存配置”即可即时生效），未构建时读取 `config.load_config()`。
- 读取当前直播间在线人数 `state.online_num`（默认为 0）。
- 判定规则：
  - 若 `r1_min <= online_num <= r1_max`：命中「区间01」，下发 `cmd1`。
  - 若 `r2_min <= online_num <= r2_max`：命中「区间02」，下发 `cmd2`。
  - 若 `r3_min <= online_num <= r3_max`：命中「区间03」，下发 `cmd3`。
  - 若 `online_num > r3_max`：按最高区间「区间03」播报。
  - 若低于 `r1_min`：按「区间01」兜底播报。
  - 若命中区间的话术内容为空，自动 fallback 到其他有内容的区间话术，防止死循环或停止。
- 同步更新 UI 状态栏：例如 `状态：直播运行｜在线 25 人 [区间01]`，并在控制台详细记录命中区间与人数。

#### (2) 彻底移除任何自动停播的逻辑（保障持续轮询）
- 彻底移除 `send_script_content` 中的自动 `_halt_live_from_worker` 停播调用：
  - 如果静音基线校准超时，记录 warning 日志，直接采用默认能量阈值（`-42.0 dB`）放行，确保话术顺利下发！
- 彻底移除 `wait_next_round_worker` 中的自动停播调用：
  - 若 `VAD_START_TIMEOUT`（豆包超时未出声）或 `VAD_AUDIO_ERROR`：记录提示日志，将 `can_next_speak = True`，立即无缝推进下一轮话术，绝不停播！
  - 只有在用户主动点击「停止直播」时，`state.is_broadcasting` 才会置为 `False`。

#### (3) 话术播完自动跳转下一轮
- 当 VAD 检测到豆包播报完毕（连续静音触发 `VAD_ENDED`），设置 `can_next_speak = True`。
- `auto_live_loop` 在每轮之间支持可配置的平滑间隔（如 1~2 秒或用户设置的执行间隔），随后立即重新采集在线人数、匹配区间、生成提示词并下发给豆包。

#### (4) 停止直播时向手机发送立即静音与停止指令
- 新增 `silence_phone_playback()` 函数：
  - 通过 ADB 发送 `KEYCODE_MEDIA_STOP` (86) 和 `KEYCODE_MEDIA_PAUSE` (127)。
  - 调用 `cmd media_session dispatch pause` 和 `cmd media_session dispatch stop`。
  - 确保手机端豆包立刻闭嘴、停止发声。
- 在 `stop_live()` 和 `cancel_active_vad()` 中：
  - 立即关闭正在采集的音频流 `_current_monitor.close()`，彻底释放虚拟声卡。
  - 停止弹幕采集 `danmu.stop_danmu_capture()` 与抓屏。
  - 恢复按钮状态为可再次启动。

### 2. [src/audio/vad.py](file:///e:/zhibodou-ai/zhibodou/src/audio/vad.py)
- 在 `wait_for_doubao_speech_cycle` 的说话中循环中，增加单轮最大播报时长安全保护（默认 180 秒），防止音频极度异常时无限等待。
- 增加等待豆包开口时间安全上限保护（确保长文本生成思考时不误切）。

## 验证计划

### 1. 在线人数区间匹配单测与模拟验证
- 编写脚本模拟不同在线人数（0人、15人、50人、120人、15000人），验证 `select_script_by_online_count()` 正确匹配到「区间01」、「区间02」、「区间03」，并在空话术时正确兜底。

### 2. 连续多轮播报闭环验证
- 启动自动直播，验证：
  - 首轮话术成功下发豆包并播放；
  - 豆包播报结束由 VAD 捕获后，日志打印切换下一轮，自动重新读取在线人数并下发第二轮话术；
  - 即使校准或开口有延迟，直播循环也绝不退出、绝不停播。

### 3. 「停止直播」静音与资源释放验证
- 在豆包正在播报过程中点击「停止直播」，验证：
  - 手机端豆包立刻停止发声；
  - 虚拟声卡流被关闭，弹幕采集和抓屏被停止；
  - 界面按钮正确恢复为待机状态，可随时重新启动。
